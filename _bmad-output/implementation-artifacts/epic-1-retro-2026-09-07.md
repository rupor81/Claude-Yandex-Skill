# Epic 1 Retrospective — Calendar connector, end to end

- **Date:** 2026-09-07
- **Scope:** stories 1.1 through 1.8, all `done`
- **Delivered:** 7 tools (`calendar_list`, `calendar_events_list`, `calendar_event_get`,
  `calendar_freebusy_query`, `calendar_event_create`, `calendar_event_update`,
  `calendar_event_delete`), 691 unit tests, 12 live tests, 12 commits
- **First retrospective on this project** — nothing to carry forward from a previous one.

---

## 1. What the epic actually proved

The epic set out to build one connector end to end and, in doing so, to settle the
shared core the other two connectors inherit. Both happened. What was not planned,
and turned out to matter more, is that the epic became a measurement of how far the
documented behaviour of this server can be trusted.

**Five measured contradictions of the documentation**, each of which would have
shipped as a plausible wrong answer rather than as a failure:

| Measured | Documented / expected |
|---|---|
| A UID search returns the whole calendar — 1759 objects for one UID | A UID search returns the matching objects |
| ETag exists only as a PROPFIND property; the GET header carries a `--gzip` suffix | The GET header carries the ETag |
| `freebusy` answers 400 on every calendar | `freebusy` is a CalDAV report |
| `If-Match` is honoured on PUT (412 for stale) but ignored on DELETE (204, removed) | Preconditions guard both |
| MKCALENDAR returns an href that is not the calendar's real address | The returned href addresses the created calendar |
| A successful conditional PUT answers 201, not 204 | 204 replaces, 201 creates |

Three of these are not guessable. The practice that found them — **measure the live
server before writing the spec** — changed every write story and is the epic's most
transferable result.

## 2. Defect classes found, and how

Three independent review layers, run in clean contexts that did not see the
implementer's reasoning, produced 180 findings across eight stories. Four classes
recurred:

**Tests that pass against broken code.** Proven by mutation at least eight times: a
line was deliberately broken, the suite stayed green. Mutation became the standard of
proof that a test is load-bearing, and is the single practice most responsible for
the suite's value.

**Fakes that validate the code against itself.** Twice. In 1.2 the `DAVClient`
fake pre-set the calendar's `.name`, so the code's own naming logic was never
exercised. In 1.4 the href comparison unquoted both sides, so `%40` agreed with
itself. Both passed. Both were wrong. The rule that follows: a fake must be built
from the *server's* observed behaviour, never from the code under test.

**Harm without a sign of harm, on write paths.** The deletion path reported a
confirmed, scoped success while removing an unrelated meeting stored in the same
CalDAV object. Review found it by *running* it rather than by reading it.

**A rule honoured at our layer and violated one below.** The `caldav` library retries
a PUT on 429, so our no-blind-retry rule was correct in our code and false in fact.

## 3. What went wrong in how the work was run

**TDD arrived at story 1.4, not 1.1.** The intent existed from the start but lived in
the arguments passed to the implementation skill, which forwards a verbatim prompt
declaring the spec the single source of truth. The instruction never reached the
implementer. Stories 1.1–1.3 were written tests-alongside-code, and that is where the
mutation-proven gaps cluster. Fixed from 1.4 onward by writing the test-first
requirement **into the spec's acceptance criteria**, where the implementer must read
it.

**Three wrong diagnoses, all mine, all plausible.**

1. Reported 62 tests as independently verified; they passed only because `PYTHONPATH`
   was set in my shell. Caught by a review layer. Root cause: macOS re-applies
   `UF_HIDDEN` to `.venv/**.pth`, and Python 3.13's `site.addpackage` skips hidden
   `.pth` files.
2. Attributed a 409 on write to server capriciousness. Actual cause: MKCALENDAR
   returned a non-real href, so writes landed elsewhere and a DELETE to that href
   answered success while removing nothing.
3. "Fixed" a flaking live test by halving the suite's cost. Real improvement, wrong
   cause: the limit is per-account and does not reset between runs, so the failure
   simply moves to whichever test is unlucky.

Two of the three came bundled with a measurable improvement, which is what made them
hard to disbelieve. The common shape is *the first plausible explanation that agrees
with what I expected*.

**A false justification was recorded in a spec as fact.** Story 1.7's change log
claimed `If-Match` against an empty href must answer 412. Measured afterwards: this
server answers **201 and creates the object**. The claim was withdrawn in place, and
the consequence — an event deleted between our read and our write is resurrected, not
refused — is now documented as an unclosable race rather than hidden.

**Artifacts were left on the operator's real account.** Three probe calendars survived
because the cleanup used the wrong URL; one live-test calendar survived a network
drop. All removed after inspecting their contents and verified by re-listing. The
live suite creates and destroys its own calendar, but a suite that dies mid-test still
leaks.

**My own bookkeeping broke twice, in the same way.** `sprint-status.yaml` sat at
`review` for all eight stories because the `review → done` transition is manual and I
never made it. `deferred-work.md` had a `## Resolved` heading inserted mid-file, so
every later append filed an open item under it — seven of them. Both defects are in
records I maintained by hand while making the underlying judgements correctly.

## 4. What carries into Epic 2

**Practices to keep, unchanged:**

- Measure the live server before writing any spec that writes. Five for five.
- Three review layers in clean contexts. 180 findings, eight proven by mutation.
- Test-first stated in the spec's acceptance criteria, not in skill arguments.
- My own mutation checks after patches, to catch "fixed" without proof.
- Inspect the account after every live run.

**The architecture held.** AD-1 through AD-12 required no amendment across eight
stories. NFR3 — no silent under-return — turned out to be a way of thinking rather
than a rule about data: it caught the incomplete list page, the "created" reported for
a destroyed meeting, and the test that could not fail.

**Debt closed before Epic 2** (chosen by the project lead): repository hygiene,
the install-mode decision, live-suite spacing, and the unknown write outcome. The
last one is not calendar-specific bookkeeping — in Mail the unknown outcome is a
**sent message**, where a blind retry sends a second one.

**Debt deliberately carried:** twelve items, all calendar-specific limits with their
reasoning recorded, in `deferred-work.md`.

### What closing them turned up

Each of the four produced evidence rather than just a tick.

**The linter's first run found 153 findings, nine of them stale `noqa` codes** — suppressions
for diagnostics that no longer fire. That is precisely the argument the debt item made: a
suppression nobody checks reads as a considered exception when it may be a leftover.

**The bookkeeping defect recurred during this retrospective.** Repairing `deferred-work.md`
dropped an entry and left the file with two `## Resolved` headings. That third instance is
why action item 5 was written as a script and run by CI rather than as a resolution to be
careful: it now reproduces all three historical defects on demand and reports each one.

**Settling the unknown write outcome exposed a missing test.** Eight mutations were run
against the new code; seven were caught and one survived — nothing covered a readback that
reached the server but could not read the version. Without it the code reported an
unreadable version as "the change was not applied", which would tell a caller to repeat a
change that may already be stored. That is the epic's own recurring defect class, caught by
the epic's own practice, on the work closing the epic.

The unit suite went from 691 to 701 tests. The formatter's one-off pass over 23 files was
verified AST-identical before being kept — the only substantive difference it made was a
space after `"""` in four test docstrings that began with a quote.

## 6. Readiness for Epic 2

**Ready.** The shared core (`errors`, `results`, `paging`, `risk`, `credentials`,
`app`) was built for three connectors and exercised by one; story 2.5 exists
specifically to correct it once a second protocol is in place, which is the right
shape. The unknowns for Mail are IMAP-side — OAuth rather than an app password,
Cyrillic folder names over IMAP (flagged unverified in the design notes and still
unmeasured), and message-body truncation — and story 2.1 begins by measuring them,
as every write story in this epic did.
