- (constraint) MCP Python SDK v2 renamed FastMCP to MCPServer; mcp.server.fastmcp.* moved to mcp.server.mcpserver.*; get_context() removed in favour of a declared ctx parameter. Most online examples target v1 and will not run
- (decision) Adopt recurring-ical-events 3.8.2 for RRULE/RDATE/EXDATE expansion and RECURRENCE-ID overrides rather than hand-rolling series expansion. Retires the largest Calendar risk from the PRD
- (constraint) Host python3 is 3.9.6, below the mcp>=3.10 floor; the toolchain pins an interpreter through uv 0.12.1 rather than touching the system Python
- (decision) AD-1 Layered paradigm chosen over hexagonal: entrypoint then tools then client, three layers per server. Hexagonal rejected because there is no shared domain for ports to serve - the layers would be empty ceremony
- (decision) AD-3 Async boundary: the tool layer is async as the SDK requires; blocking caldav and imap clients are invoked only through anyio.to_thread.run_sync inside the client layer, never from tools. Prevents a half-async codebase and a stalled event loop
- (decision) AD-4 Completeness enforced by type, not convention: Page for listings and Chunk for text, both carrying complete and next_cursor. Chosen so NFR3 cannot be forgotten on the twentieth tool
- (decision) Adversarial pass found that Page alone left text truncation uncovered - mail_message_get truncates bodies. Chunk added to close the hole
- (decision) Testing: protocol-level fakes for fast offline unit tests plus a small live smoke suite gated behind an environment variable. Cassette record/replay rejected because cassettes of a real mailbox carry personal data needing scrubbing
- (decision) AD-8 Tool naming scheme <server>_<object>_<verb>, uniform across all three servers
- (change) PRD tool names are inconsistent (calendar_list vs events_list, mail_messages_list vs disk_list). AD-8 renames them; the PRD must be amended so upstream and spine do not diverge
